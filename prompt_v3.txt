================================================================================
FLASH (AS1) -> HTML5 CONVERSION PROMPT  --  ACCESSIBLE / KL-UNL PIPELINE MODE
For Claude Code. One decompiled sim folder in; an accessible HTML5 sim that plugs
into the KL-UNL foundation, out. Functionality identical to the original; layout
and chrome follow the KL-UNL pipeline + accessibility guidelines (NOT the old Flash
pixel layout).
================================================================================

ROLE
You convert a legacy Adobe Flash astronomy simulation (already decompiled with JPEXS
/ FFDec) into a self-contained, ADA-Title-II / WCAG 2.1 AA HTML5 simulation that
behaves identically to the original and is built on the shared KL-UNL foundation
files. You will NOT run Flash, Ruffle, or any emulator. Your ground truth for
BEHAVIOR is the decompiled ActionScript (AS1: prototype classes via
Object.registerClass, onEnterFrame + getTimer(), SOME art drawn in code via
createEmptyMovieClip/drawArc/beginFill/lineTo/curveTo/attachMovie) plus EXPORTED
assets -- bitmaps in images/ and vector shapes in shapes/ -- which are REUSED AS-IS,
never redrawn. Your ground truth for CHROME, STYLE, and LAYOUT is the KL-UNL foundation
files and the accessibility rules below.

--------------------------------------------------------------------------------
TWO GOALS, AND HOW THEY RELATE
--------------------------------------------------------------------------------
GOAL A -- FUNCTIONAL PARITY (hard, exact):
  Same controls, same drag behavior, same animations, same randomized decay/
  recombination logic, same state transitions, same physics constants/tables/
  formulas, same on-screen/log/dialog TEXT and the same number formatting. Copy
  every constant and every piece of educational text VERBATIM from the source.

GOAL B -- ACCESSIBLE KL-UNL PRESENTATION (hard):
  The sim is rendered inside the KL-UNL shell using the foundation files, follows
  the WCAG 2.1 AA rules below, and therefore does NOT reproduce the original Flash
  pixel layout, palette, fonts, or masthead. Layout fidelity means PANEL STRUCTURE
  and pedagogical grouping (which panels exist, what each contains, their reading
  order), expressed with KL-UNL CSS classes -- not original coordinates.

If A and B conflict (e.g. a color-coded state, an unstoppable animation, a missing
Reset), satisfy B (accessibility) and record the deviation in CONVERSION_NOTES.md.
Behavior of the underlying physics/logic is never changed to satisfy B -- only its
presentation (color, motion, labeling, controls) adapts.

--------------------------------------------------------------------------------
THE KL-UNL FOUNDATION (in the linked folder; copied in UNCHANGED; do not edit the code)
--------------------------------------------------------------------------------
THE LINKED SIM FOLDER CONTAINS a foundation/ subfolder holding the KL-UNL files
(kl-unl-masthead.js, contents.json, kl-unl.css, kl-unl.js, and any MathJax include the
demo uses). You must COPY that whole foundation/ folder, BYTE-FOR-BYTE UNCHANGED, into
html5/foundation/ in the output (see OUTPUT section for the exact layout). The ONLY file
whose CONTENT you may change is the COPIED per-sim contents.json, and only by ADDING this
sim's entry (see THE ONE PERMITTED CONTENTS EDIT). Never edit kl-unl-masthead.js,
kl-unl.css, or kl-unl.js.

Find the foundation/ folder at the root of the linked sim folder (beside scripts/,
shapes/, the .fla/.swf, etc.). If it is absent or missing one of the four files, STOP and
ask -- do not invent them or fetch them from anywhere.

Because index.html lives in html5/ and the foundation files live in html5/foundation/,
the HTML is exactly one level above the foundation folder. This matches the masthead
component's own internal defaults (it references ../foundation/contents.json and
../foundation/kl-unl.css relative to ITSELF, i.e. relative to html5/foundation/, which
resolves to html5/...). Pass json-url="foundation/contents.json" from the <kl-unl-
masthead> tag (path relative to index.html), and link the CSS/JS from index.html as
"foundation/kl-unl.css" and "foundation/kl-unl.js". Do not rewrite the paths INSIDE
the foundation files to make this work -- the one-level layout already lines them up.

What the foundation files do:
  - kl-unl-masthead.js : a Shadow-DOM custom element <kl-unl-masthead> that renders
      the title bar plus Reset / Help / About buttons and their modal dialog, reading
      its text from contents.json by sim-id. It dispatches a bubbling, composed
      CustomEvent "sim-reset" when Reset is pressed. Help/About content comes from
      contents.json; the component manages the dialog, focus, and Escape itself.
  - contents.json : per-sim data keyed by sim-id -> { meta:{title,version},
      masthead:{ help:{title,content}, about:{title,content} } }. Help content of ""
      (empty string) means NO Help button is shown.
  - kl-unl.css : shared palette (CSS custom properties like --foreground-color,
      --background-color, --button-*, --alert-color-*, --outline-color) and layout
      classes: .app-shell, .app-shell__backdrop, .app-layout (+ __left/__right),
      .panel (+ __heading/__canvas-wrap/__help), .control-fieldset (+ __legend),
      .control-row (+ __label/__input/__slider, --axes), .control-grid,
      .control-choice, .button, .button-row, .modal/.modal-content/.close, .sr-only,
      :focus-visible handling, and responsive @media rules.
  - kl-unl.js : MathJax equation helper. klunlShowEquation(eqn[,msg1[,msg2]]) updates
      a LaTeX equation container (by id) and up to two screen-reader message elements;
      klunlInitEqn() is called on load and is meant to be REDEFINED in your sim JS to
      initialize equations/components. Use these for any displayed equations.

--------------------------------------------------------------------------------
HARD RULES
--------------------------------------------------------------------------------
1. Behavior matches the original exactly (Goal A). Constants, tables, formulas, and
   all educational/log/dialog text are VERBATIM from the AS source. Never round a
   constant or paraphrase educational text.
2. Presentation follows KL-UNL + WCAG (Goal B). Use the foundation CSS classes and
   custom properties; do not hardcode the old Flash colors/fonts/coordinates.
3. Use the <kl-unl-masthead> component for the title + Reset/Help/About. Do NOT build
   your own masthead, your own About/Help dialog, or your own Reset button. Listen for
   the "sim-reset" event and reset the sim's state to its exact initial state.
4. Help/About text lives in the sim's contents.json entry (verbatim from the original,
   reflowed into the existing boilerplate pattern) -- not hardcoded in the sim.
5. Self-contained, no external dependencies: no build step, no bundler, no framework,
   no CDN, no analytics, no Google Fonts. All files are local. The page IS served over
   HTTP (local static server in dev, cloud host in production) -- it is NOT expected to
   run from a double-clicked file:// path, because the masthead fetches foundation/
   contents.json and browsers block fetch() over file://. The only runtime fetches are
   local (foundation/contents.json) plus the foundation's own MathJax include if the demo
   uses one; nothing leaves the host. Vanilla HTML/CSS/JS, <script type="module"> is fine.
   index.html references the foundation files copied into html5/foundation/ (e.g.
   foundation/kl-unl.css, foundation/kl-unl.js, foundation/kl-unl-masthead.js) and passes
   json-url="foundation/contents.json". Ship an html5/README.md explaining how to serve
   it and why file:// double-click fails.
6. Single source of truth for state: one plain JS state object; a single render()
   redraws everything from state after every action, so canvas, DOM, and the aria-live
   region stay in sync.
7. Do not modify any decompiled source file, and do not modify the CODE of any KL-UNL
   foundation file (kl-unl-masthead.js, kl-unl.css, kl-unl.js) -- they are copied into
   html5/foundation/ unchanged. The only permitted content change is adding this sim's
   entry to the per-sim copy of contents.json.
8. MathJax for ALL mathematics (MUST). Every mathematical equation, formula, variable,
   or expression shown to the user is rendered with MathJax via the foundation's
   kl-unl.js (klunlShowEquation / klunlInitEqn) using LaTeX -- never as a raster image,
   plain-text ASCII math, or hand-built HTML/sub/sup. This applies to readouts and log
   entries that contain real math notation too. Pair each equation with a screen-reader
   message string (kl-unl.js supports this) so the math is also spoken.
9. Never put sim styling inside the KL-UNL foundation files, and never inline overrides
   that fork their look. If a control needs styling the foundation doesn't provide
   (e.g. a custom slider), do NOT edit kl-unl.css or kl-unl.js and do NOT paste a big
   <style> block into index.html to override them. Instead build a SEPARATE, additional
   component in the sim's own styles/styles.css (and simulation.js) -- e.g. a custom
   accessible slider -- layered on top of the foundation without modifying it. Keep
   foundation files byte-for-byte unchanged (only the contents.json entry is added).
10. Larger, zoomable text. Use comfortably large, readable type (body text noticeably
   larger than browser default; treat ~1.125rem as a floor for body copy and scale
   headings/labels up accordingly), sized in rem/em so it tracks the user's browser font
   setting. The layout MUST remain usable and not clip or overlap when the page is zoomed
   to 200% (WCAG 1.4.4 / 1.4.10 reflow): use relative units, allow wrapping, avoid fixed
   px heights that crop text. Canvas-internal labels that must stay legible should prefer
   being moved into surrounding HTML (which zooms) rather than baked into the scaled
   canvas; note any that cannot in ACCESSIBILITY.md.
11. Responsive incl. mobile portrait. Beyond the iPad floor, the page must also reflow
   gracefully to narrow/portrait widths (phone portrait): single-column stacked layout,
   panels full-width in reading order, no horizontal scrolling, controls and canvas
   fitting the viewport. Use the KL-UNL responsive grid plus sim-specific breakpoints in
   styles/styles.css (never by editing the foundation) so it transitions from the
   desktop/iPad multi-column layout to a stacked portrait layout as width decreases.

RENDERING ARCHITECTURE
--------------------------------------------------------------------------------
HYBRID, inside the KL-UNL shell:
  - Use the KL-UNL structural classes for the page skeleton: an .app-shell wrapping
    <kl-unl-masthead> + an .app-layout of .panel sections that mirror the original's
    panel grouping and reading order (e.g. diagram panel, controls panel, event-log
    panel). Use .control-fieldset / .control-row / .control-grid / .control-choice /
    .button / .button-row for controls.

  - REUSE EXPORTED ASSETS; DO NOT REDRAW THEM. The JPEXS export contains real exported
    art -- bitmaps in images/ (photos, textures, logos -- e.g. a photo of a person) and
    vector shapes in shapes/*.svg. These must be USED AS-IS, never recreated by hand.
    Copy each asset the sim actually uses into html5/assets/ and reference that copy.
    Decide per visual element using this PREFERENCE ORDER:
      1. Exported BITMAP (images/*.png, or a bitmap-backed symbol) -> use the file
         directly: draw with ctx.drawImage on the canvas at the same position/size, OR
         place as a positioned <img> with appropriate alt text (prefer <img> when it is
         a standalone informative/decorative picture like a photo; prefer drawImage when
         it must composite/animate with canvas art). Never trace or redraw a bitmap.
      2. Exported VECTOR SHAPE (shapes/*.svg) for static art -> reuse the SVG file as-is
         (inline <svg>, <img>, or drawImage of the SVG). Do not re-vectorize it by hand.
      3. ONLY genuinely CODE-DRAWN geometry -- art the ActionScript builds at runtime via
         createEmptyMovieClip / drawArc / beginFill / lineTo / curveTo / attachMovie
         (orbits, electron dots, photon trails, energy bars, masks) -> reproduce with
         canvas 2D drawing, since there is no exported file for it.
    When unsure whether an element is an exported asset or code-drawn, check the symbol
    in symbolClass/symbols.csv and the matching shapes/sprites/images entry; if a file
    exists for it, REUSE the file. Match original placement, size, and z-order. Copy the
    fonts the sim uses into html5/assets/ too if they are sim-specific (shared fonts may
    come from the foundation).

  - Render the simulation "stage" (the code-drawn art and animation from preference #3
    above: orbits, electrons, photons, proton, energy bars, markers, masks) on an HTML5
    <canvas> placed inside a .panel__canvas-wrap, compositing the reused bitmaps/SVGs
    (#1/#2) at their original positions. Recreate only the code-drawn AS calls on the 2D
    context, preserving geometry and motion (see AS1 idiom notes). The canvas is the
    visual layer; it is NOT the accessibility layer.
  - Native, semantic controls for everything interactive: <button>, <input
    type="range">, <input>/<select>/<output>, <label>, <fieldset>/<legend>. Never a
    <div onclick>. These provide keyboard + screen-reader access that a canvas cannot.
  - For any draggable canvas object (e.g. dragging the electron between levels),
    provide BOTH the pointer drag (matching the original offset + nearest-level
    snapping math) AND an equivalent keyboard/native control (e.g. arrow-key handling
    with role="slider" semantics, or a labeled select/stepper) so the action is fully
    keyboard-operable. Both paths mutate the same state.
  - Displayed equations go through kl-unl.js (klunlShowEquation) with LaTeX + screen-
    reader message strings; redefine klunlInitEqn() in your sim JS to set them up.

--------------------------------------------------------------------------------
AS1 IDIOM TRANSLATION (this collection's actual patterns)
--------------------------------------------------------------------------------
- Object.registerClass("Symbol Name", Foo) + Foo.prototype = new MovieClip()
    -> a plain JS class/constructor Foo with the same methods; the symbol becomes a
       logical object you draw/position on the canvas.
- Constructor/drawing code (createEmptyMovieClip, lineStyle, beginFill, moveTo,
  lineTo, curveTo, drawArc, endFill) -> canvas 2D drawing with the SAME coordinates,
  radii, and color/alpha values. AS color ints are decimal RGB (16777215=#FFFFFF,
  65280=#00FF00); fill/line alpha is 0-100 -> divide by 100. (You may re-map colors to
  the KL-UNL palette where required for contrast/colorblind safety -- but record every
  such change in ACCESSIBILITY.md and never use color as the only signal.)
- Custom MovieClip.prototype.drawArc (tessellates with curveTo): ctx.arc reproduces it;
  match center, radius, start/end angle. AS uses screen-Y-down with sin negated
  (y - r*sin); mirror that so orbital motion direction matches.
- onEnterFrame -> a single requestAnimationFrame loop. getTimer() -> performance.now()
  (ms). Keep the SAME timing constants (e.g. 2500 ms) and use elapsed wall-clock time,
  not frame counts, so timing matches across machines. updateAfterEvent() -> no-op.
- Drag (onPress sets onMouseMove; onRelease/onReleaseOutside clears it; uses _xmouse,
  xOffset, snapping to nearest of levelPositions[], plus a "ghost" electron alpha)
  -> pointer events with identical offset + nearest-snapping math AND a keyboard path.
- _x/_y/_alpha/_visible/_rotation/_xscale -> object props applied at draw time;
  _rotation is DEGREES (convert for Math trig).
- attachMovie("Linkage", name, depth, initObj) -> instantiate the matching JS object,
  apply initObj, insert into a depth-ordered draw list.
- setMask / mask clips -> ctx.save + clip() with the same region.
- Number.prototype.toFixed polyfill / scientific notation -> reproduce the EXACT
  on-screen/log formatting (digits, "x 10^n", sign).
- FUIComponent / FPushButton / FScrollBar -> do NOT port the Flash component framework;
  reproduce only the observable behavior using native accessible controls.
- _root/_parent chains -> explicit references between your JS objects. trace() -> drop.

--------------------------------------------------------------------------------
ACCESSIBILITY REQUIREMENTS (WCAG 2.1 AA baseline; AAA where reasonable)
--------------------------------------------------------------------------------
Semantics & structure
  - One <h1> = the simulation name (the masthead component renders the title; do not
    add a competing h1). Correct, non-skipping heading hierarchy for panels.
  - Semantic landmarks: <main>, <section>, <header>/<nav> (from masthead), <aside> for
    the event log if appropriate. Use the KL-UNL classes on these elements.
Text alternatives (1.1.1)
  - Decorative canvas/SVG/img: aria-hidden / alt="". Informative canvas: provide a text
    equivalent reachable by screen readers -- a concise live/description region that
    states what the diagram currently shows (e.g. electron level, last transition).
  - Equations: use kl-unl.js message args to give a spoken description alongside LaTeX.
Color & contrast (1.4.1/1.4.3/1.4.11)
  - >=4.5:1 text, >=3:1 large/graphical. Use the KL-UNL palette variables. NEVER encode
    state by color alone -- add a label, shape, or text (e.g. "656 nm - H-alpha (red)").
    Keep physically meaningful spectra but supplement with numeric/textual labels.
Keyboard (2.1.1/2.1.2/2.4.7)
  - Everything operable by keyboard in a logical tab order; visible :focus-visible ring
    (provided by kl-unl.css). No keyboard traps. The masthead dialog already traps/
    restores focus -- don't fight it.
  - SLIDERS MUST BE FULLY KEYBOARD-OPERABLE (current sims get "stuck" here -- fix it).
    Every slider is focusable and adjustable by keyboard: Left/Down decrement, Right/Up
    increment, PageUp/PageDown for larger steps, Home/End for min/max. Prefer a native
    <input type="range"> (it gives all of this for free) with a real <label>, a sensible
    step, and aria-valuetext where a formatted/unit value should be announced. If a
    CUSTOM slider is required for styling, build it as a separate component (per hard
    rule 9, in styles/styles.css + simulation.js, never by editing foundation files):
    give it tabindex="0", role="slider", aria-valuemin/max/now (and aria-valuetext), and
    handle the same arrow/Page/Home/End keys. Ensure the focused control is not blocked
    by canvas pointer handlers, doesn't lose focus mid-drag, and that focus never gets
    trapped on it (Tab must move away normally). Changing a slider updates the same state
    object as the pointer path, so keyboard and mouse stay in sync.
Timing / motion (2.2.2/2.3.3)
  - No motion >5 s without a stop; nothing flashes >3x/sec. Honor prefers-reduced-
    motion: replace continuous animation with the equivalent instantaneous end state.
  - Provide Pause if the sim has long-running motion. (Reset is provided by the
    masthead via the sim-reset event -- wire it; do not add a second Reset button.)
Live region (status)
  - An aria-live="polite" region announces meaningful state changes (e.g. "Electron now
    on level 3. Photon energy 12.09 eV: Lyman-beta absorbed."). Announce slider results
    on release/commit, not on every tick. Keep wording consistent with on-screen text.
Forms & language
  - Every input has a real <label> (or fieldset/legend). <html lang="en">.

--------------------------------------------------------------------------------
RESPONSIVENESS (desktop -> iPad -> phone portrait)
--------------------------------------------------------------------------------
The result must be usable and well-laid-out across the range from desktop down to
phone PORTRAIT width. iPad (~768-1024px) is the primary tablet target; the layout must
ALSO reflow gracefully to narrow phone-portrait widths (single column, no horizontal
scroll). It must remain usable at 200% browser zoom (treat zoom-induced narrow widths
the same as small viewports -- reflow, don't clip).

Shell / layout
  - Lean on the KL-UNL responsive system already in kl-unl.css: rem-based sizing,
    .app-shell max-width, the .app-layout grid, and its @media (max-width: 56rem) rule
    that collapses two columns to one. Build the panel structure with those classes so
    the collapse happens for free; do not hardcode pixel widths that fight it.
  - Sim-specific styles in styles/styles.css use relative units (rem/%/fr, min()/max()/
    clamp()) and avoid fixed px widths on containers. Add sim-specific breakpoints in
    styles/styles.css as needed (NEVER by editing the foundation) to carry the layout
    below the foundation's 56rem breakpoint down to phone portrait; keep the foundation's
    own 56rem behavior intact.

Phone portrait
  - At narrow/portrait widths, stack everything into ONE column in logical reading order
    (e.g. title, diagram/canvas panel, controls, event log), each panel full-width.
  - No horizontal scrolling; nothing clipped or overlapping. Controls wrap instead of
    overflowing; the canvas panel shrinks to fit the viewport width (the SCALE approach
    below handles the canvas itself).
  - Keep tap targets >=44px and spacing comfortable for touch in the stacked layout.

Canvas stage (SCALE, do not reflow)
  - Keep the simulation's ORIGINAL internal coordinate system. All ported drawing/
    physics math stays in original Flash stage coordinates -- do NOT recompute positions
    or radii from the live element size (that risks parity drift). Set the canvas backing
    resolution to the original stage size (optionally multiplied by window.devicePixel-
    Ratio for crispness, with a matching ctx.scale), and let CSS scale the canvas element
    to fit its panel while preserving aspect ratio (e.g. max-width:100%; height:auto, or
    an aspect-ratio box). The drawing code never needs to know the on-screen size.
  - Map pointer/touch coordinates back through the current scale factor so hit-testing
    and the electron-drag offset/snapping math operate in original stage coordinates and
    keep matching the AS source exactly at any display size.

Touch (tablets and phones have no hover and use touch)
  - Use Pointer Events (pointerdown/move/up) so mouse and touch share one path. On any
    draggable canvas element set CSS touch-action:none so dragging doesn't scroll/zoom
    the page; restore normal scrolling elsewhere.
  - Ensure interactive targets meet the >=44px (2.75rem) min size the KL-UNL .button and
    control styles already provide; don't shrink them below that on smaller widths.
  - Do not rely on :hover to reveal controls or information (no hover-only affordances).

The html5/ folder is fully self-contained: index.html sits one level above

RUNNING IT REQUIRES AN HTTP SERVER -- it will NOT work by double-clicking index.html.
The masthead component (kl-unl-masthead.js, which you must not modify) loads its title/
Help/About text via fetch('foundation/contents.json'). Browsers block fetch() of local
files under the file:// protocol (CORS / same-origin), so opening index.html directly
shows an empty or broken masthead. Served over HTTP (a local static server during dev,
or the cloud host in production) the fetch succeeds and the sim loads normally. The
required README.md must explain exactly this -- see the README spec below.

THE html5/README.md MUST CONTAIN:
  - A one-line statement that the sim must be served over HTTP and will not run from a
    double-clicked file:// path.
  - WHY: the KL-UNL masthead fetches foundation/contents.json, and browsers block fetch()
    over file:// for security (same-origin policy), so the title/Help/About won't load.
  - HOW TO RUN locally, with copy-paste commands the user can run from inside the html5/
    folder, e.g.:
      Python:  python3 -m http.server 8123   then open http://localhost:8123/
      Node:    npx serve        (or npx http-server)
      VS Code: the "Live Server" extension
    (Note the sim is at the server root when you serve from inside html5/, so the URL is
    http://localhost:8123/ -- not .../html5/index.html.)
  - A one-line production note: when deployed to the cloud host (served over HTTP/HTTPS)
    it just works; the file:// limitation only affects local double-clicking.
